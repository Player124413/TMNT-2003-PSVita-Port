# Android-порт TMNT (2003)

Неофициальный порт статической рекомпиляции из этого репозитория. APK содержит **только код порта**
(SDL2, gl4es, рантайм, лаунчер). Код и данные игры не входят в APK и не скачиваются портом.

## Что нужно

- Телефон/планшет с **32-битным ARM `armeabi-v7a`** и Android 8.0+ (API 26), OpenGL ES 2.0.
  Современные устройства только с 64-битными приложениями не поддерживаются: гостевые указатели
  в рекомпиляции 32-битные. Лаунчер показывает понятное сообщение на таком устройстве.
- Собственная поддерживаемая PC-версия: `TMNT_EN.EXE` SHA-1
  `4e56dd020e9b3c9fdf755f3d655fd5f2a84e4777`, 2 150 400 байт, и данные рядом с ним.
- Для сборки APK: JDK 17, Android SDK 35, NDK **27.2.12479018**, CMake 3.22.1, Python 3.8+.
- Для создания игрового пакета: тот же NDK, Python-пакеты `pefile` и `capstone`
  (`pip install -r tools/vita_code/requirements.txt`).

## Быстрый старт с готовым APK

1. Установите `TMNT-2003-android-debug.apk`. Это отладочная сборка с временным ключом подписи,
   не релиз для магазина.
2. На компьютере соберите игровой пакет из своей копии игры:

   ```sh
   python3 tools/make_android_files.py /путь/к/игре ~/TMNT.tmnt.zip \
       --ndk /путь/к/Android/Sdk/ndk/27.2.12479018
   ```

   Если APK уже собран в этом дереве, генератор найдёт рантайм в
   `build/android-runtime/armeabi-v7a/libtmnt_runtime.so`. Иначе передайте `--runtime` путь к
   **той же версии** `libtmnt_runtime.so`, что установлена в APK.
3. Скопируйте `TMNT.tmnt.zip` на телефон и в лаунчер нажмите **Импортировать файлы игры**.
   Импорт идёт через системный выбор файла, проверяет SHA-256 каждого файла и не требует
   разрешения на доступ ко всему хранилищу.
4. Нажмите **Играть**. Кнопка **Пауза** в левом верхнем углу открывает меню; оттуда можно
   изменить раскладку или вернуться в лаунчер.

Пакет содержит `pack.json`, `image.bin`, `tmnt_code.so`, `TMNT.DAT`, `TMNT_V00.DAT`,
`TMNT_V01.DAT`, `TMNT_V02.DAT`, `bgm.afs`, `se.afs`, `voice.afs`. Не публикуйте его.
Сохранения игры и раскладка хранятся отдельно от импортированных файлов и переживают замену пакета.

## Сборка APK из исходников

```sh
python3 tools/android/fetch_deps.py
cd android
./gradlew :app:assembleDebug
```

APK появится в `android/app/build/outputs/apk/debug/`. Gradle сам скачает AGP/SDK-зависимости;
`local.properties` должен указывать на Android SDK (`sdk.dir=...`) или задайте `ANDROID_HOME`.
Сборка использует только `armeabi-v7a`. Не добавляйте `arm64-v8a` без портирования гостевой модели указателей.

После сборки APK создайте игровой пакет командой выше. Порядок важен: `tmnt_code.so` линкуется
с рантаймом из APK и получает `DT_NEEDED libtmnt_runtime.so`.

## Сенсорное управление

- Лаунчер → **Настроить сенсорные кнопки**: перетаскивание, размер, прозрачность, действие,
  общая прозрачность, мёртвая зона стика, виброотклик, отмена и сброс.
- Раскладка хранится в нормализованных координатах безопасной области и адаптируется к размеру экрана.
- Мультитач: у каждого пальца свой захват; стик и кнопки работают одновременно. Уход пальца с кнопки
  не передаёт её случайно другому пальцу. `ACTION_CANCEL`, сворачивание и пауза сбрасывают ввод.
- Физические геймпады SDL работают параллельно: A/B/X/Y — удары/прыжок/сюрикен, LB — рывок,
  RB — жонглирование, LB+RB — спецприём, Back — смена черепахи, Start — старт/меню.
- Редактор не внедряет код в игру и не требует перезапуска APK.

## Производительность, 60 FPS и ETC2

В лаунчере есть профили **Баланс**, **Прохладный** и **Максимум**, масштаб внутреннего разрешения
25–100%, сохранение пропорций 4:3, звук и оверлей FPS/времени кадра.

Оптимизации порта:

- отдельный поток рендера и арена команд между игровым и графическим потоками;
- кэширование состояний GL, статических VBO/IBO, отложенное удаление ресурсов;
- NEON-конвертация массовых форматов вершин/текстур;
- внутренний RGBA8 + depth24/stencil8 FBO и один масштабирующий blit на кадр вместо чтения пикселей CPU;
- GLES2-контекст SDL, gl4es поверх GLES, кэш бинарных шейдеров в приватном каталоге;
- 48 kHz S16 stereo, короткие аудио-буферы; пауза без уничтожения GL-контекста.

**60 FPS — цель, не гарантия.** Оригинальная игра имеет 30-тиковую логику и места с ограничением
30 FPS. Профиль «Максимум» снимает ограничения порта, но не создаёт новые уникальные кадры анимации
там, где игра их не рисует. Измеряйте оверлеем FPS на конкретном телефоне; начинайте с 75% масштаба.
В этой среде не было реального Android-устройства, поэтому замеры производительности и совместимость
с драйверами GPU ещё не подтверждены.

**ETC2 сейчас не нужен.** Исходные DXT1/3/5 не являются ETC2. gl4es распаковывает DXT при загрузке
текстуры в обычные RGBA-текстуры GLES; покадровая конвертация не выполняется. Это совместимо с ES2,
но тратит память и время при загрузке. ETC2 имеет смысл только как отдельная офлайн-транскодировка
после замеров памяти/загрузок и только для ES3-устройств; простая замена enum DXT на ETC2 неверна.

## Архитектура и безопасность загрузки

- `rt/android/plat_android.c`: окно/EGL SDL, аудио, геймпады, FBO, пауза, скриншоты.
- `rt/android/touch.c`, `bridge.c`: атомарное состояние ввода UI → игра, без JNI в горячем пути рендера.
- `rt/android/code_android.c`: `dlopen`/`dlsym` пользовательского Bionic-модуля, проверка `TNMC`/версии.
  Vita ELF-loader не используется. Файл делается read-only до загрузки (требование Android 14+).
- `GameActivity` работает в отдельном процессе `:game`; лаунчер/редактор остаются живы при выходе игры.
- Импорт ограничен 3 GiB, фиксированным списком имён, размером и SHA-256; запись атомарная через staging.
- Нет разрешения `INTERNET`, микрофона или общего доступа к хранилищу.

## Проверки

```sh
python3 tools/android/test_android.py
cc -std=c11 -I. tools/android/test_touch.c rt/android/touch.c -o build/test_touch && build/test_touch
cd android && ./gradlew :app:lintDebug
```

Перед релизом обязательны реальные проверки: импорт/повторный импорт/отмена, холодный старт, пауза/фон,
поворот, вырез экрана, геймпад, звук после звонка, сохранение/загрузка, фильмы, длинные игровые сессии,
нагрев и FPS на минимальном и целевом устройствах.
