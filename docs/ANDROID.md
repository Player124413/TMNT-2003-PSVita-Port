# Android-порт TMNT (2003)

Неофициальный порт статической рекомпиляции из этого репозитория. Обычный (**clean**) APK содержит
**только код порта** (SDL2, gl4es, рантайм, лаунчер); код и данные игры импортируются отдельным пакетом.
Есть также **приватный APK**, в который при сборке встраиваются `tmnt_code.so` и `image.bin`; после его
установки лаунчер импортирует только данные установленной PC-игры. Приватный APK нельзя публиковать.

## Что нужно

- Телефон/планшет с ARM и Android 8.0+ (API 26), OpenGL ES 2.0. Поддерживаются **`arm64-v8a`**
  (современные 64-битные устройства) и **`armeabi-v7a`** (старые 32-битные). APK собирается под одну
  ABI; выберите артефакт/сборку под процессор телефона. Гостевые адреса остаются 32-битными смещениями,
  но Android-рантайм на AArch64 использует нативные host-указатели. Лаунчер проверяет ABI APK.
- Собственная поддерживаемая PC-версия: `TMNT_EN.EXE` SHA-1
  `4e56dd020e9b3c9fdf755f3d655fd5f2a84e4777`, 2 150 400 байт, и данные рядом с ним.
- Для сборки APK: JDK 17, Android SDK 35, NDK **27.2.12479018**, CMake 3.22.1, Python 3.8+.
- Для создания игрового пакета: тот же NDK, Python-пакеты `pefile` и `capstone`
  (`pip install -r tools/vita_code/requirements.txt`).

## Быстрый старт с готовым APK

1. Установите `TMNT-2003-android-debug.apk`. Это отладочная сборка с временным ключом подписи,
   не релиз для магазина.
2. На компьютере соберите игровой пакет из своей копии игры:

   ```sh
   python3 tools/make_android_files.py /путь/к/игре ~/TMNT.tmnt.zip \
       --abi arm64-v8a --ndk /путь/к/Android/Sdk/ndk/27.2.12479018
   ```

   Если APK уже собран в этом дереве, генератор найдёт рантайм в
   `build/android-runtime/arm64-v8a/libtmnt_runtime.so` (или `armeabi-v7a`, если собран 32-битный APK).
   Иначе передайте `--runtime` путь к
   **той же версии** `libtmnt_runtime.so`, что установлена в APK.
3. Скопируйте `TMNT.tmnt.zip` на телефон и в лаунчер нажмите **Импортировать файлы игры**.
   Импорт идёт через системный выбор файла, проверяет SHA-256 каждого файла и не требует
   разрешения на доступ ко всему хранилищу.
4. Нажмите **Играть**. Кнопка **Пауза** в левом верхнем углу открывает меню; оттуда можно
   изменить раскладку или вернуться в лаунчер.

Пакет содержит `pack.json`, `image.bin`, `tmnt_code.so`, `TMNT.DAT`, `TMNT_V00.DAT`,
`TMNT_V01.DAT`, `TMNT_V02.DAT`, `bgm.afs`, `se.afs`, `voice.afs`. Не публикуйте его.
Сохранения игры и раскладка хранятся отдельно от импортированных файлов и переживают замену пакета.

## GitHub Actions

Workflow `.github/workflows/android.yml` собирает APK на `ubuntu-24.04` с JDK 17, Android SDK 35,
NDK 27.2.12479018 и CMake 3.22.1. Он запускается на push в `main`/`arena/**`, на pull request и вручную
(`workflow_dispatch`). Push/PR собирают и проверяют **обе ABI** отдельными job; ручной запуск с URL
использует выбранный `target_abi` (по умолчанию `arm64-v8a`).

Что проверяется:
- host-тесты генератора пакета и атомарного touch-ввода;
- сборка `:app:assembleDebug` и `:app:lintDebug`;
- подпись APK, выравнивание (для `arm64-v8a` также 16 KiB pages), manifest, ABI и отсутствие игровых данных внутри APK;
- линковка синтетического `tmnt_code.so` с рантаймом из APK и создание тестового `.tmnt.zip`.

Артефакты `TMNT-2003-android-debug-apk-arm64-v8a` и `TMNT-2003-android-debug-apk-armeabi-v7a`
содержат устанавливаемый APK, совместимый `libtmnt_runtime.so` и SHA-256. Соответствующие
`android-build-reports-<abi>` содержат lint-отчёты и синтетический пакет. Синтетический пакет
**не является игрой**: он нужен только для проверки формата и ABI. Обычный APK-workflow не скачивает
игру и не публикует игровые файлы. Реальный пакет можно создать локально из собственной копии игры
или отдельным ручным workflow ниже; во втором случае игровой артефакт будет **публичным**. Для
приватного результата есть локальная сборка и workflow приватного APK (см. ниже).

## Сборка игрового пакета по ссылке на ZIP

Ручной запуск GitHub Actions принимает ссылку на ZIP вашей установленной PC-версии, скачивает и безопасно
распаковывает архив, проверяет поддерживаемый `TMNT_EN.EXE`, статически рекомпилирует код и собирает готовый
`TMNT.tmnt.zip`. Основной вход: **Android APK → Run workflow** с заполненным `game_zip_url`; он вызывает
reusable workflow `.github/workflows/android-game-pack.yml` («Android game pack from URL»). В том же запуске
собираются APK и `libtmnt_runtime.so`, поэтому пакет и рантайм гарантированно совпадают.

Как запустить:

1. Откройте **Actions → Android APK → Run workflow**. Выберите ветку и вставьте `game_zip_url` —
   прямую HTTPS-ссылку на ZIP-архив установленной игры. Это должен быть именно архив с
   `TMNT_EN.EXE` и данными, а не страница облака/редирект на HTML. Если оставить `game_zip_url`
   пустым, тот же workflow соберет обычный APK без игровых данных.
   Отдельный пункт **Android game pack from URL** — это тот же reusable workflow напрямую; GitHub может
   показывать его только после того, как файл попадёт в ветку по умолчанию (например, после слияния PR).
2. Обязательно включите `confirm_public_artifact`. Этот репозиторий публичный, поэтому артефакт
   с файлами, полученными из игры, сможет скачать любой. Используйте только свою копию и только если
   вам разрешено её распространять. Для приватного результата не включайте `confirm_public_artifact`,
   а включите `private_apk` в приватном репозитории либо используйте локальный
   `tools/android/build_private_apk.py`.
3. После успешного запуска скачайте артефакты:
   - `TMNT-2003-android-debug-apk-<abi>` — APK, совместимый `libtmnt_runtime.so`, SHA-256;
   - `TMNT-2003-game-pack-PUBLIC-<abi>` — `TMNT.tmnt.zip`, отдельные `tmnt_code.so`/`image.bin`,
     `SHA256SUMS.txt`, `BUILD-INFO.txt`, `README-IMPORT.txt`.
4. Установите APK из этого запуска и импортируйте в лаунчере **`TMNT.tmnt.zip`**. Отдельный
   `tmnt_code.so` не является пакетом для импорта: лаунчеру нужны все 9 файлов и `pack.json`.

Ограничения и проверки загрузчика:

- только HTTPS, порт 443, ASCII/Punycode URL, без логина/пароля в URL и без фрагмента;
- не вставляйте в ссылку секретные токены: параметры запуска workflow могут быть видны пользователям
  репозитория, даже если сам загрузчик не печатает URL в логах;
- DNS-ответы проверяются на публичные адреса и закрепляются для TLS-соединения; редиректы ограничены;
- лимиты: 4 GiB скачивание, 6 GiB распакованный размер, 50 000 записей, 30 минут на скачивание;
- ZIP проверяется до распаковки: запрещены обход пути, symlink/special files, дубликаты имён,
  шифрованные записи; проверяются CRC и размеры;
- поддерживается только `TMNT_EN.EXE` SHA-1 `4e56dd020e9b3c9fdf755f3d655fd5f2a84e4777`;
- перед загрузкой артефакта проверяются `pack.json`, точный список файлов, размеры, SHA-256,
  ELF ARM/AArch64 для заявленной ABI, зависимость от `libtmnt_runtime.so` и экспорт `tmnt_code`.

Игровой артефакт хранится **1 день** (`retention-days: 1`). Исходный ZIP, распакованная игра и
промежуточный рекомпилированный C не коммитятся и удаляются на runner перед загрузкой артефакта.

## Приватный APK со встроенными кодом и image.bin

Этот вариант делает именно то, что обычно хочется от «готового» APK: `tmnt_code.so` упакован как
`lib/<abi>/libtmnt_code.so`, `image.bin` лежит в `assets/tmnt/image.bin` и один раз извлекается в
приватный каталог приложения. После установки не нужно импортировать `.tmnt.zip`, `tmnt_code.so` или
`image.bin`: лаунчер просит только **данные той же установленной PC-игры** — ZIP установленной игры или
папку игры, скопированную на телефон. Семь файлов (`TMNT_EN.DAT`/`TMNT.DAT`, `TMNT_V00.DAT`,
`TMNT_V01.DAT`, `TMNT_V02.DAT`, `bgm.afs`, `se.afs`, `voice.afs`) проверяются по размеру и SHA-256,
записанным при сборке APK. EXE и прочие файлы из ZIP игнорируются.

Локальная сборка (ничего не загружается в GitHub):

```sh
python3 tools/android/build_private_apk.py /путь/к/установленной/игре TMNT-2003-private.apk \
    --abi arm64-v8a --ndk /путь/к/Android/Sdk/ndk/27.2.12479018
```

Нужны JDK 17, Android SDK 35, NDK 27.2.12479018, CMake 3.22.1 и Python-пакеты из
`tools/vita_code/requirements.txt`. Скрипт сначала собирает рантайм, затем рекомпилирует ваш EXE,
встраивает код/образ, пересобирает APK и проверяет его. Результат — `TMNT-2003-private.apk` и файл
`.sha256`. Промежуточные файлы остаются только в ignored `build/`.

Через GitHub Actions: **Android APK → Run workflow**, заполнить `game_zip_url` и включить
`private_apk` и выбрать `target_abi`. Workflow `.github/workflows/android-private-apk.yml` сначала проверяет через GitHub API,
что репозиторий **приватный**; в публичном репозитории он падает до скачивания игры. В приватном
репозитории артефакт `TMNT-2003-private-apk-<abi>-PRIVATE` доступен только пользователям с доступом к
репозиторию и хранится 7 дней. Не делайте репозиторий публичным, пока такой артефакт существует.

Установка и импорт:

1. Установите приватный APK. Его application id — `org.tmnt.port.private`, он может сосуществовать с
   обычным APK.
2. В лаунчере нажмите **Импортировать установленную PC-игру** и выберите ZIP или папку той же игры,
   из которой собран APK. Можно сначала скопировать папку игры на телефон; широкого разрешения на
   хранилище не требуется, используется системный выбор файла/папки.
3. Нажмите **Играть**. Сохранения, раскладка и настройки хранятся отдельно от импортированных данных.

Ограничения: приватный APK привязан к конкретному EXE, образу, рантайму и хешам данных. Если данные
отличаются, импорт откажет и назовёт отсутствующие/несовпадающие файлы. Это не способ распространять
игру: APK содержит производный от игры код и образ, поэтому держите его приватным.

## Сборка APK из исходников

```sh
python3 tools/android/fetch_deps.py
cd android
./gradlew -PtmntAbi=arm64-v8a :app:assembleDebug
```

APK появится в `android/app/build/outputs/apk/debug/`. Gradle сам скачает AGP/SDK-зависимости;
`local.properties` должен указывать на Android SDK (`sdk.dir=...`) или задайте `ANDROID_HOME`.
По умолчанию собирается `armeabi-v7a`; для 64-битных телефонов передайте `-PtmntAbi=arm64-v8a`.
Один APK содержит одну ABI, чтобы игровой пакет и embedded-манифест всегда соответствовали процессу.

После сборки APK создайте игровой пакет командой выше. Порядок важен: `tmnt_code.so` линкуется
с рантаймом из APK и получает `DT_NEEDED libtmnt_runtime.so`.

## Сенсорное управление

- Лаунчер → **Настроить сенсорные кнопки**: перетаскивание, размер, прозрачность, действие,
  общая прозрачность, мёртвая зона стика, виброотклик, отмена и сброс.
- Раскладка хранится в нормализованных координатах безопасной области и адаптируется к размеру экрана.
- Мультитач: у каждого пальца свой захват; стик и кнопки работают одновременно. Уход пальца с кнопки
  не передаёт её случайно другому пальцу. `ACTION_CANCEL`, сворачивание и пауза сбрасывают ввод.
- Физические геймпады SDL работают параллельно: A/B/X/Y — удары/прыжок/сюрикен, LB — рывок,
  RB — жонглирование, LB+RB — спецприём, Back — смена черепахи, Start — старт/меню.
- Редактор не внедряет код в игру и не требует перезапуска APK.

## Производительность, 60 FPS и ETC2

В лаунчере есть профили **Баланс**, **Прохладный** и **Максимум**, масштаб внутреннего разрешения
25–100%, сохранение пропорций 4:3, звук и оверлей FPS/времени кадра.

Оптимизации порта:

- отдельный поток рендера и арена команд между игровым и графическим потоками;
- кэширование состояний GL, статических VBO/IBO, отложенное удаление ресурсов;
- NEON-конвертация массовых форматов вершин/текстур;
- внутренний RGBA8 + depth24/stencil8 FBO и один масштабирующий blit на кадр вместо чтения пикселей CPU;
- GLES2-контекст SDL, gl4es поверх GLES, кэш бинарных шейдеров в приватном каталоге;
- 48 kHz S16 stereo, короткие аудио-буферы; пауза без уничтожения GL-контекста.

**60 FPS — цель, не гарантия.** Оригинальная игра имеет 30-тиковую логику и места с ограничением
30 FPS. Профиль «Максимум» снимает ограничения порта, но не создаёт новые уникальные кадры анимации
там, где игра их не рисует. Измеряйте оверлеем FPS на конкретном телефоне; начинайте с 75% масштаба.
В этой среде не было реального Android-устройства, поэтому замеры производительности и совместимость
с драйверами GPU ещё не подтверждены.

**ETC2 сейчас не нужен.** Исходные DXT1/3/5 не являются ETC2. gl4es распаковывает DXT при загрузке
текстуры в обычные RGBA-текстуры GLES; покадровая конвертация не выполняется. Это совместимо с ES2,
но тратит память и время при загрузке. ETC2 имеет смысл только как отдельная офлайн-транскодировка
после замеров памяти/загрузок и только для ES3-устройств; простая замена enum DXT на ETC2 неверна.

## Архитектура и безопасность загрузки

- `rt/android/plat_android.c`: окно/EGL SDL, аудио, геймпады, FBO, пауза, скриншоты.
- `rt/android/touch.c`, `bridge.c`: атомарное состояние ввода UI → игра, без JNI в горячем пути рендера.
- `rt/android/code_android.c`: `dlopen`/`dlsym` Bionic-модуля, проверка `TNMC`/версии. В clean APK это
  импортированный `tmnt_code.so` (делается read-only до загрузки, требование Android 14+); в приватном
  APK — `libtmnt_code.so` из native-библиотек самого APK. Vita ELF-loader не используется.
- `EmbeddedGame`/`InstalledGameImporter`: приватный APK извлекает `image.bin` из assets и импортирует
  только семь PC-данных, сверяя их с хешами, записанными при сборке APK. Код из хранилища не загружается.
- `GameActivity` работает в отдельном процессе `:game`; лаунчер/редактор остаются живы при выходе игры.
- Импорт ограничен 3 GiB, фиксированным списком имён, размером и SHA-256; запись атомарная через staging.
- Приватный CI-workflow отклоняет публичный репозиторий до скачивания игры; артефакты публичного
  репозитория не используются для приватного APK.
- Нет разрешения `INTERNET`, микрофона или общего доступа к хранилищу.

## Проверки

```sh
python3 tools/android/test_android.py
python3 tools/android/test_game_zip.py
python3 tools/android/test_embedded.py
cc -std=c11 -I. tools/android/test_touch.c rt/android/touch.c -o build/test_touch && build/test_touch
cd android && ./gradlew :app:lintDebug
```

Перед релизом обязательны реальные проверки: импорт/повторный импорт/отмена, холодный старт, пауза/фон,
поворот, вырез экрана, геймпад, звук после звонка, сохранение/загрузка, фильмы, длинные игровые сессии,
нагрев и FPS на минимальном и целевом устройствах.
